# Fusion decision landscape

An investigator-facing explanation of *why RadioFry accepted, rejected or rerouted a
signal*, plus the CNN observations that fell out of building it.

| | |
|---|---|
| Core | `src/radiofry/fusion/decision_landscape.py` |
| Page | `gui/pages/12_fusion_landscape.py` (stage 12) |
| Tests | `tests/test_decision_landscape.py` (28), `tests/test_advanced_pages.py` (7 page tests) |
| Explains | `src/radiofry/fusion/confidence_fusion.py` — **unmodified** |

## The design decision that matters

The landscape is **generated by calling `fuse_modulation` itself**, once per grid cell. It
does not re-derive, approximate or model the rules. Re-implementing them in a second place
is precisely the failure this feature exists to prevent: a plausible diagram that quietly
stops matching the code. Because the map *is* the implementation sampled, the tests can
assert cell-by-cell equality against direct calls, and a future change to a threshold
shows up in the picture automatically.

## Why SNR is not an axis

The task brief suggested CNN confidence x classical confidence x SNR. Reading the
implementation first showed that **SNR is not an argument to `fuse_modulation` and no
threshold in the fusion code refers to it**. The call site in `pipeline.py` passes only:

```
fuse_modulation(prediction.label, prediction.confidence, classical.family,
                alternatives=..., ranked_alternatives=...,
                classical_evidence=classical.evidence,
                classical_confidence=classical.confidence)
```

SNR shapes those inputs upstream — a noisy capture yields a less confident CNN and
different envelope statistics — but it does not enter the decision. Plotting it as a
decision axis would have invented a dimension the logic does not have, which the brief
explicitly forbids. It is therefore reported as measured context for the capture, and the
axes are the two continuous quantities fusion actually reads:

- **x — CNN confidence**, where the 0.4 acceptance threshold lives.
- **y — classical confidence**, where the 0.5 digital-family sufficiency floor lives.

Everything else fusion reads is categorical (CNN label, classical family, ranked
alternatives, envelope evidence) and is carried in `LandscapeScenario`, selectable in the
UI so an analyst can see the guards a capture did *not* trigger.

## The exact rules visualized

Evaluated in this priority order, matching `fuse_modulation` top to bottom:

| # | Branch | Condition | Outcome |
|---|---|---|---|
| 1 | Analog subtype gate (Entry 032) | `classical_family == "analog-like"` and envelope evidence supplied | `WBFM` if `envelope_flatness > 0.40`; else `AM-SSB` if `amplitude_cv >= 0.37`; else `AM-DSB`. CNN does not vote. |
| 2 | Digital-family guard (Entry 034) | CNN label in `{AM-DSB, AM-SSB, WBFM}` **and** classical family in `{PSK-like, FSK-like, QAM-like}` **and** classical confidence `>= 0.5` | Reroute to the best digital alternative if it clears the threshold, else block to `Unclassified` |
| 3 | Analog recovery (Entry 026) | rejected (`p < threshold`) **and** classical says analog **and** CNN top-1 is not analog | Recover the highest-ranked analog alternative |
| 4 | Default | — | `Unclassified` if `p < threshold`, else the CNN label |

Trust score: `min(1, p*1.1)` when the CNN label's family matches the classical family,
`p*0.5` when it does not. Review is flagged when rejected **or** when the families
disagree. This is an explicit agreement heuristic, not a calibrated probability, and the
page says so.

The seven regions the UI draws — accepted, accepted-with-review, analog subtype, analog
recovery, guard reroute, guard block, rejected — are classified from the returned
`FusionResult`'s own fields (`digital_family_block`, `analog_route`, `label`,
`review_recommended`) rather than from a copy of the conditions, so a new guard keeps
being described correctly rather than being silently mislabelled.

## Assumptions and limitations

- **Alternatives are held fixed while top-1 confidence sweeps.** In a real softmax they
  co-vary (the vector sums to one). Holding them at the values the capture actually
  produced avoids inventing a model, but it means the reroute/block boundary of branch 2
  does not move along the CNN axis as it would in reality. Stated on the page.
- **Discontinuous by nature.** Fusion is a chain of threshold rules, so regions meet at
  hard edges. The heatmap shows them as hard edges.
- **Not a probability surface.** Nothing here is learned. The 3D height is the trust
  heuristic, not a likelihood.
- **`reproduced` check.** `describe_capture` replays the recorded inputs through the real
  function; if the result disagrees with the recorded decision the page refuses to present
  the point as belonging to the landscape.

## Performance

An 81x81 map is 6,561 calls to a pure-Python function with no array work. The full
`tests/test_decision_landscape.py` suite — which builds many grids, including six
cell-by-cell equality sweeps — runs in **0.20 s**. Grids are cached on the scenario.

# CNN observations (measurement only — nothing was changed)

> ### ⚠ These numbers describe the OLD checkpoint, not production
>
> Everything in this section is read from `reports/benchmark_v039/results.pkl`, and
> `benchmark_v039/config.json` records `checkpoint: models_saved/modulation_cnn.pt` — the
> **11-class RadioML model**. Production has been `modulation_cnn_v3_spsaug.pt` since
> Entry 040. **Do not read these as statements about the production CNN.**
>
> Measured on the same grid, production v3 gives (BANK.md Entry 041):
>
> | | Entry 039 record (below) | production v3 |
> |---|---|---|
> | CNN top-1 | 38.5% | **93.3%** |
> | sps 32 top-1 | 7.5% | **90.0%** |
> | wrong at confidence ≥ 0.9 | 39 | **0** |
>
> In particular the calibration finding in §6 is **reversed** on production: v3's worst
> wrong answer sits at confidence 0.683, with zero errors above 0.7 out of 376
> predictions. The section is kept because it documents the fusion behaviour that was
> measured at the time, and because the guards it describes are still the guards the
> landscape draws.

Read from `reports/benchmark_v039/results.pkl` (480 digital captures, Entry 039). **No
retraining, no architecture change, no checkpoint change, no threshold change.**

### 1. BPSK and QPSK are *not* confused with each other

| | |
|---|---|
| true BPSK → CNN BPSK | 38 / 60 |
| true QPSK → CNN QPSK | 28 / 60 |
| BPSK ↔ QPSK cross-confusions | **1 in 120** |

This matters for Track A: conjugate SCD is theoretically the right discriminator for
BPSK vs QPSK, and it works (10/10 on real captures) — but **the CNN does not actually make
that mistake**. Both classes fail to *other* labels. Conjugate SCD should therefore be
presented as independent constellation evidence, not as a fix for a measured CNN weakness.

### 2. QAM16 / QAM64 are the real confusion pair

| true | CNN top-1 | most common predictions |
|---|---|---|
| QAM16 | 13 / 60 | QAM16 13, PAM4 12, QAM64 10, WBFM 8 |
| QAM64 | 15 / 60 | **QAM16 22**, QAM64 15, PAM4 9, GFSK 7 |

QAM64 → QAM16 is the single largest confusion in the benchmark.

### 3. SPS 4 and 32 are where it collapses

| sps | CNN top-1 | fused |
|---|---|---|
| 4 | 47/120 (39.2%) | 17/120 (14.2%) |
| 8 | 82/120 (68.3%) | 71/120 (59.2%) |
| 16 | 47/120 (39.2%) | 44/120 (36.7%) |
| 32 | **9/120 (7.5%)** | **8/120 (6.7%)** |

### 4. Confidently wrong predictions

39 wrong at confidence ≥ 0.9; 30 at ≥ 0.95; **13 at ≥ 0.99**. Dominated by
CPFSK→GFSK (13), GFSK→WBFM (9), CPFSK→WBFM (6) — and concentrated at sps 16 (13) and
sps 32 (15). The GFSK→WBFM cases are what the Entry 034 guard exists to catch.

### 5. The classical detector cannot see PSK

| true | what the classical detector says |
|---|---|
| BPSK | QAM-like 36, FSK-like 23, PSK-like **1** |
| QPSK | QAM-like 36, FSK-like 24, PSK-like **0** |
| 8PSK | QAM-like 36, FSK-like 23, PSK-like **0** |

Overall classical family accuracy is 229/480 (47.7%), but it is 60/60 for PAM4, QAM16 and
QAM64 and ~0/60 for all three PSK classes.

**Consequence for fusion:** of 185 *correct* CNN predictions, the classical family agreed
only 71 times (38.4%) — so **114 correct predictions had their trust halved** by the
agreement heuristic. This is a property of the classical detector's PSK blindness, not of
the CNN.

### 6. What the acceptance threshold actually does

At the production threshold of 0.4 it cuts 47 correct CNN predictions and 94 incorrect
ones — roughly two wrong for every right, so the gate is doing useful work. But precision
barely moves across the whole usable range:

| threshold | kept right | kept wrong | precision |
|---|---|---|---|
| 0.20 | 179 | 275 | 39.4% |
| 0.40 (production) | 138 | 201 | 40.7% |
| 0.50 | 116 | 142 | 45.0% |
| 0.60 | 89 | 114 | 43.8% |

**The CNN's confidence separates right from wrong only weakly on this benchmark.** A
well-calibrated model would show precision climbing steeply as the threshold rises; here
it moves ~5 points while recall halves. Fusion corrected 2 wrong CNN top-1s and rejected
47 correct ones (all to `Unclassified`, all with confidence between 0.160 and 0.399,
30 of them at sps 4).

### Candidate future experiments — all four now answered (Entry 041)

These were listed here as open questions. They were subsequently measured, and none of
them survived as an action:

1. ~~**Confidence calibration**~~ — **not needed.** Production v3 has zero wrong
   predictions above 0.683 confidence; the weak precision-vs-threshold curve below was a
   property of the 11-class checkpoint.
2. ~~**QAM16/QAM64 separability**~~ — **measured and closed.** The penultimate embedding
   shows a separation ratio of 0.46 with 25.8% centroid overlap (`docs/SIGNAL_DNA.md`),
   and Entry 041 proved the confusion is **information-limited, not model-limited**: a
   discriminator given 64× the data, oracle timing and a threshold fitted on the test set
   reaches only 58.3% at 0 dB, while the CNN scores 77.5% at 5 dB against that same
   bound's 73.3%. The lever is capture length, not the model.
3. ~~**sps 32**~~ — **fixed by Entry 040.** v3 scores 90.0–95.5% at sps 32 against the
   7.5% recorded below.
4. ~~**Classical PSK detection**~~ — **measured and rejected.** Entry 041 found the root
   causes (`amplitude_cv` ≈ 0.215 for *every* constant-envelope class; the fourth-power
   statistic is structurally blind to 8PSK's 8-fold symmetry) and established that no rule
   on the current four features separates the families — best 87% from `frequency_cv`
   alone. Since the blindness costs trust scores and review flags rather than labels, and
   the same thresholds carry the analog safety gate, it was left unchanged.

**No CNN change is currently justified by any measurement in this repository.**
